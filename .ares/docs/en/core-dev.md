# @ares/core-dev Documentation

## Purpose

`@ares/core-dev` is a **unified yargs CLI** + dev utilities to **scaffold and maintain** projects built on top of `@ares/core`, with a focus on:

- bootstrapping an aReS project (appSetup + datasources + policies layout);
- datasource setup (config + folder layout via driver presets);
- migrations and their execution (`migration make` / `migration run`);
- mappers and their wiring (`mapper create` / `mapper execute`);
- AI-assisted documentation generation and revision (`docs generate` / `docs revise`);
- AI-assisted prompt library management (`prompt save` / `prompt run`);
- AI integration diagnostics (`ai-doctor`);
- delegation to `@ares/scd` for prompt/docs/ticket generation and code analysis (`make`, `work ticket`, `analyze code`);
- **driver presets** (only MySQL today; list is extensible via `DRIVER_PRESETS`).

This module is a "builder/developer-side tool" and is NOT loaded at runtime by production apps. It interfaces in a repeatable way with `@ares/datasource-files` and `@ares/core` migrations runtime.

## Installation

Declared in `package.json`:

```json
{
  "type": "module",
  "bin": { "ares-core-dev": "./index.js" },
  "exports": {
    ".": "./src/cli.js",
    "./cli": "./index.js",
    "./presets/mysql": "./presets/mysql.js"
  },
  "dependencies": {
    "@ares/core": "workspace:^",
    "@ares/datasource-files": "workspace:^",
    "@ares/os": "workspace:^",
    "@ares/scd": "workspace:^",
    "yargs": "^17.7.2"
  }
}
```

Yarn Workspaces monorepo:

```bash
yarn workspace <app> add @ares/core-dev --dev
yarn add -W @ares/core-dev --dev
```

## Quickstart

Full workflow with the **unified `ares-core-dev` CLI** (single ESM yargs entrypoint):

```bash
# 1. General help / subcommand list
ares-core-dev --help

# 2. Bootstrap a new aReS project
ares-core-dev project init --project-dir ./my-app --project-name my-app

# 3. Add a MySQL datasource
cd ./my-app
ares-core-dev datasource add --name users --driver mysql --host localhost --port 3306 --user root --password secret --database users

# 4. List existing datasources
ares-core-dev datasource list --datasource-dir ./datasources

# 5. Create a manual migration
ares-core-dev migration make --name "Add phone column" --datasource users

# 6. Run pending / rolled-back migrations
ares-core-dev migration run --datasource users --env test --force

# 7. Create a mapper on a datasource
ares-core-dev mapper create --datasource users --name find-by-email --params "email:string:true" --type sql

# 8. Execute a mapper
ares-core-dev mapper execute users find-by-email --params '{"email":"a@b.c"}'

# 9. Run the project test script
ares-core-dev test

# 10. AI diagnostics
ares-core-dev ai-doctor --json
```

## Public CLI (single entrypoint `ares-core-dev`)

> **Adopted strategy**: Option B — single entrypoint + yargs subcommands. Legacy scripts `make-migration.js`, `migrate.js`, `make-mapper.js` are retained as backward-compat wrappers.

The CLI is fully localized (`it`/`en`, auto-detected via `@ares/os`). Use `--help` on any command group for the accurate, human-readable help.

### `ares-core-dev project init`

Bootstraps a new aReS project with the standard baseline structure:

- `appSetup/` (with `appSetup/index.js`, `appSetup/config/default.js`, `appSetup/policies/default.js`);
- `datasources/`;
- `db/migrations/`;
- `.ares/context/`, `.ares/tasks/`, `.ares/gantt/`, `.ares/docs/it/`, `.ares/docs/en/`.

Params (`runProjectInit({ projectDir, projectName, force })`):
- `--project-dir` (string, default `process.cwd()`) — target directory.
- `--project-name` (string, default: directory name) — logical project name.
- `--force, -f` (boolean, default `false`) — overwrite existing base files (e.g. `appSetup/index.js`).

### `ares-core-dev datasource add`

Creates a complete driver datasource via preset (`runDatasourceAdd`).

Params:
- `--name, -n` (required) — datasource name (= folder name).
- `--driver, -d, -drv` (default `mysql`; choices from `SUPPORTED_DRIVERS`, today `['mysql']`).
- `--datasource-dir, -D, --root` (default `$ARES_DATASOURCES_ROOT` or `./datasources`).
- MySQL connection params: `--host`, `--user`, `--password`, `--database, -db`, `--port`, `--schema`.
- `--force, -f` (boolean) — overwrite if exists.

Files created under `<ds-root>/<name>/`:
- `datasource.js` (with `aReSInitialize`, test/production environments + `autoInstallSchema`);
- `current-schemas.json` (schema generated by preset);
- `migrations/` (empty ready folder);
- `queries/` (empty mapper folder).

### `ares-core-dev datasource list`

Lists all subfolders under `<datasource-dir>` containing `datasource.js` / `index.js`. No extra options.

### `ares-core-dev datasource remove`

Removes an existing datasource folder (destructive).

Params:
- `--name, -n` (required).
- `--force, -f` (boolean, default `true`).

### `ares-core-dev migration make`

Scaffolds a manual migration skeleton (`runMakeMigration`).

Required: `--name, -n`, `--datasource, -d, -ds`.
Optional: `--datasource-dir, -D` (default `$ARES_DATASOURCES_ROOT` or `./datasources`).

### `ares-core-dev migration run`

Runs pending / rolled-back / failed migrations via `installDatasourceWithMigrations` (`runMigrate`).

Required: `--datasource, -d, -ds`.
Optional:
- `--name, -n` — run only the named migration (by name or timestamp prefix);
- `--force, -f` — force re-run, bypassing some safety checks;
- `--env, -e, --environment` (`test`|`production`|`prod`, default `test`);
- `--datasource-dir, -D`.

Exit code: `0` on success, `10` if any migration failed.

### `ares-core-dev mapper create`

Creates `<datasource>/queries/<mapper-name>.js` with an ESM skeleton (`runMapperCreate` / `runMakeMapper`).

Params:
- `--name, -n` (required) — query/mapper name.
- `--datasource, -d, -ds` (required) — owning datasource.
- `--params, -p` (required) — comma-separated parameter list `name:type:required`.
- `--type, -q, --query-type` (required; choices `sql|url|json|xml|xsl`).
- `--datasource-dir, -D` (default `./datasources`).

### `ares-core-dev mapper execute <datasource> <mapper>`

Executes a mapper with params from file / URL / inline JSON (`runMapperExecute`).

- Positional `<datasource>` — datasource name (or `--datasource`).
- Positional `<mapper>` — mapper/query name (or `--mapper`).
- `--json, -j, --params` (default `""`) — params as `file.json` path | `http(s)` URL | inline JSON `'{...}'`.
- `--env, -e, --environment` (`test`|`production`, default `test`).
- `--session-id, -sid` — optional datasource session id.

### `ares-core-dev test [scriptName]`

Runs a `package.json` script (`runTest`).

- Positional `scriptName` (default `"test"`) — package.json script name.
- `--project-dir` (default `process.cwd()`).

### `ares-core-dev docs generate`

AI-assisted documentation generation (`runDocsGenerate`). Writes docs to `.ares/docs/<lang>/`.

Params (group-level flags `--sample`, `--project-id`, `--json` apply to all three docs/prompt commands):
- `--scope, -S, --dir` (required) — scope directory to analyse (e.g. `./core`).
- `--lang, -l` (`it`|`en`, default `it`).
- `--instructions, -i, --instr` (default `""`) — additional free-text instructions for the AI.
- `--sample, -s`, `--project-id`, `--json, -j`.

### `ares-core-dev docs revise`

AI-assisted single-file documentation revision (`runDocsRevise`).

- `--file, -f, -F` (required) — path to the `.md` file to revise.
- `--lang, -l` (`it`|`en`, default `it`).
- `--instructions, -i, --instr` (default `""`).
- `--sample, -s`, `--project-id`, `--json, -j`.

### `ares-core-dev prompt save`

Saves a restructured prompt to `.prompt/<timestamp>-<slug>.md` (`runPromptSave`).

- `--text, -t` (default `""`) — prompt text (can also be piped from stdin).
- `--output-dir, -o, --dir` (default `.prompt`).
- `--title-hint, --title` (default `""`).
- `--sample, -s`, `--project-id`, `--json, -j`.

### `ares-core-dev prompt run`

Runs an AI capability (`runPromptRun`).

- `--text, -t` (default `""`) — prompt text (can also be piped from stdin).
- `--capability, -c, --cap` (default `answer_question`; choices `answer_question|prompt_refactor|generate_docs|analyze_code|suggest_migrations|scaffold_code|generate_tests|code_refactor`).
- `--force-provider, -p, --provider` (default `null`) — force a provider (e.g. `openai`, `anthropic`).
- `--context-json, -ctx` (default `null`) — additional context in JSON.
- `--session-id, -sid` — AI session id.
- `--sample, -s`, `--project-id`, `--json, -j`.

### `ares-core-dev ai-doctor`

AI integration diagnostics (`runAIDoctor`): checks bridge availability, sample mode, bridge mode, prompt dir default, docs/prompt commands, and next steps.

- `--sample, -s`, `--json, -j`.

### `ares-core-dev make <command>` (bridged to `@ares/scd`)

Delegates to `@ares/scd`:
- `make prompt [--path|-p] [--text|-t] [--output-dir|-o] [--scope|-S] [--title-hint] [--title|-T] [--sample|-s] [--json|-j]`;
- `make docs [--scope|-S] [--lang|-l it|en] [--instructions|-i] [--sample|-s] [--json|-j]`;
- `make ticket [--path|-p] [--text|-t] [--output-dir|-o default .ares/tasks] [--title-hint] [--sample|-s] [--json|-j]`.

### `ares-core-dev work ticket <filename>` (bridged to `@ares/scd`)

Works an existing ticket checklist. Positional `<filename>` required; `--output|-o`, `--sample|-s`, `--json|-j`.

### `ares-core-dev analyze code` (bridged to `@ares/scd`)

Analyzes code and generates suggested tickets in `.ares/tasks/suggested/`. Options `--scope|-S|--dir` (default cwd), `--max-depth|-d|--depth` (default `3`), `--output|-o`, `--sample|-s`, `--json|-j`.

## Public APIs (exports)

### Root entrypoint `@ares/core-dev` (package `"."` → `src/cli.js`)

The reusable logic (no CLI-start side effects). Named exports:

- `DRIVER_PRESETS` (`{ mysql: mysqlPreset }`), `SUPPORTED_DRIVERS` (`['mysql']`);
- `detectLanguage()`, `toSnakeCase()`, `formatTimestamp()`, `resolveDatasourcesRoot()`, `locateDatasourceFile()`;
- `runMakeMapper`, `runMakeMigration`, `runMigrate`, `runProjectInit`, `runDatasourceAdd`, `runDatasourceList`, `runDatasourceRemove`, `runMapperCreate`, `runTest`, `runDocsGenerate`, `runDocsRevise`, `runPromptSave`, `runPromptRun`, `runAIDoctor`, `runMapperExecute`;
- default export object re-exposing all of the above.

### Subpath `@ares/core-dev/cli` → `index.js`

The ESM bin entrypoint (yargs). NOT to be imported as a library (runs `cli.parseAsync()` at top level).

### Subpath `@ares/core-dev/presets/mysql`

Stable exports:
- `buildDatasourceModule({ name, host, user, password, database, port })` → source-code string for `datasource.js`;
- `buildDefaultSchemasJson({ schemaName })` → `current-schemas.json` object.

## Configuration / environment

- `$ARES_DATASOURCES_ROOT` — fallback for `--datasource-dir` / `--root` if not passed.
- `isProduction` — controlled via `--env production`; forwarded to `aReSInitialize`.
- Language: `it`/`en` auto-detected via `@ares/os` `getCurrentOSLanguage()` (default `en`); the CLI help/descriptions are localized inline in `index.js`.
- `DRIVER_PRESETS` (future extension): to add Mongo/Qdrant/Files edit `src/cli.js` + add `presets/<driver>.js`.
- The legacy `localization/languages/{en,it}.js` files are no longer used by the CLI.

## Backward-compat wrappers (CJS → ESM)

To avoid breaking legacy scripts, these package-root files exist:

| Script | Behaviour |
|---|---|
| `make-mapper.js`     | CJS → `import('./src/cli.js').then(m => m.runMakeMapper(parseCli()))` |
| `make-migration.js`  | CJS → `child_process.spawn('node ./index.js migration make …')` with stdio inherit |
| `migrate.js`         | CJS → `child_process.spawn('node ./index.js migration run …')` with stdio inherit |

## Notes

- Binary convention: `ares-core-dev` (kebab-case, linear).
- Only MySQL is implemented today (other drivers are planned via tickets).
- The `docs`/`prompt`/`ai-doctor` commands use the AI bridge (`@ares/ai-3rd-party`); `--sample` runs them in offline/stub mode.
- `make`, `work ticket` and `analyze code` are inherited from `@ares/scd` (dynamically imported or spawned as a subprocess).
- See Phases 1–2 in `../../application-managing-report.md` for integration with `dev-test-server` and the hybrid job runner.
